# ARUS DOMOD

Интернет-магазин таджикского свадебного костюма: **продажа и прокат** нарядов
для невесты и жениха, украшений и аксессуаров. Дом моды из Душанбе.

Это рабочий магазин, а не макет: каталог и заказы живут в базе, заказ уходит
владельцу в WhatsApp, товарами и статусами управляет админ-панель, интерфейс
говорит на трёх языках — русском, таджикском и английском. Онлайн-оплаты нет
**по решению**: оплата и доставка согласовываются с клиентом лично, место под
Alif подготовлено и подключается отдельной задачей.

```bash
cp .env.example .env.local   # задать ADMIN_PASSWORD и ADMIN_SESSION_SECRET
npm install
npm run dev                  # http://localhost:3000  ·  админка /admin
```

Нужен **Node 24**: база — встроенный модуль `node:sqlite`, без зависимостей.
Предупреждение `ExperimentalWarning: SQLite` при старте ожидаемо.

## Что это

Сайт устроен как **саҳн** — белый двор, на котором стоят **айвоны**: глубокие
зелёные объёмы с настоящей тенью, а в их нишах — фотографии. У каждого блока
своя композиция: кадр выходит из объёма на белое, объём сдвигается под кадр,
рейка карточек уходит за край, карточка лежит на углу. Золото — нить в
облицовке: линия, цифра, угол, шов. Типографика журнальная: имя дома больше
страницы, номера коллекции антиквой, вертикальные подписи на рейках.

Национальное здесь работает внутри luxury fashion, а не вместо него.

| Раздел                | Что там                                                          |
| --------------------- | ---------------------------------------------------------------- |
| `/`                   | Главная: hero, категории, подборка, прокат, «как заказать»       |
| `/catalog`            | Каталог с фасетными фильтрами, сортировкой и поиском             |
| `/catalog/[category]` | Тот же каталог с предвыбранным разделом                          |
| `/product/[slug]`     | Страница образа: галерея, покупка **или** условия проката        |
| `/rental`             | Условия проката: до 3 дней, от 100 сомони, залог, только в магазине |
| `/about` · `/delivery` · `/contacts` | Страницы дома — только подтверждённые данные      |
| `/cart` · `/favorites`| Корзина (панель и страница) и избранное — `localStorage`         |
| `/checkout`           | Оформление: заказ сохраняется в базу и уходит в WhatsApp         |
| `/admin`              | Админ-панель: товары, категории, кадры, заказы и их статусы      |

## Как проходит заказ

1. Клиент собирает корзину и заполняет форму на `/checkout` (имя, телефон,
   город, дата свадьбы, комментарий).
2. `POST /api/orders` проверяет строки по каталогу, снимает цены на момент
   заказа и пишет заказ в SQLite с номером вида `AD-0001` и статусом «Новый».
3. Экран «принято» открывает WhatsApp с готовым текстом заказа — Азизе
   (основной номер) или Рустаму. Сообщение можно и скопировать.
4. В `/admin/orders` заказ виден сразу; статус ведётся вручную: Новый → На
   подтверждении → Подтверждён → Ожидает оплаты → Оплачен → Передан в
   доставку → Доставлен → Завершён, либо Отменён.

**Прокат через сайт не оформляется.** На странице образа это отдельная вкладка
с условиями и кнопкой «Узнать о прокате» — она тоже ведёт в WhatsApp; договор
и залог (деньги, паспорт или золото) — только в магазине, без доставки.

## Стек

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS v4 ·
`node:sqlite`.

Зависимости ровно те, что создаёт `create-next-app`. Ни одной библиотеки сверх
этого: анимации, иконки, орнаменты, база, сессии админки и загрузка кадров
сделаны своими средствами.

## Настройка и данные

| Переменная             | Зачем                                                        |
| ---------------------- | ------------------------------------------------------------ |
| `ADMIN_PASSWORD`       | Пароль входа в `/admin`. Без него админка не открывается     |
| `ADMIN_SESSION_SECRET` | Подпись сессионной куки, `openssl rand -hex 32`              |
| `ARUS_DATA_DIR`        | Где лежат база и загрузки, по умолчанию `./data`             |

При первом запуске создаётся `data/arus.sqlite` и заполняется демо-каталогом
из `src/lib/catalog/mock-data.ts`. Кадры, загруженные через админку, лежат в
`data/uploads/` и отдаются маршрутом `/uploads/…` (папка `public/` в сборке
заморожена). Каталог `data/` в git не попадает.

**Деплой** — долгоживущий Node-процесс с постоянным диском (VPS, Docker, PM2):
база и загрузки — файлы. Бессерверные платформы вроде Vercel не подходят без
замены хранилища.

## Языки

Язык переключается в шапке и хранится в куке `arus_locale` (`ru` · `tg` ·
`en`); адреса страниц одни на все языки. Словари — `src/lib/i18n/`. На сервере
текст берётся через `getDictionary()`, в клиентских компонентах — через
`useDictionary()`; тип словаря выводится из русского, поэтому пропущенный ключ
в переводе не соберётся. Названия образов — данные, они не переводятся.

### Два решения, которые стоит знать до первой правки

**Шов данных.** Страницы и компоненты никогда не читают товары напрямую.
Серверный код берёт `catalog()` из `src/lib/catalog` (SQLite), клиентский —
из `src/lib/catalog/client` (тот же контракт поверх `/api/catalog`). Один
движок запросов `engine.ts` обслуживает обе двери, поэтому фильтры и фасеты
считаются одинаково. Деньги — целые минорные единицы с кодом валюты; цена
живёт в `offers[]`, потому что образ может и продаваться, и сдаваться в прокат.

**Поверхности.** Тон задаётся атрибутом `data-surface` на секции (`night` ·
`green` · `day`), а не классами на элементах: внутри переключаются все
семантические токены сразу. Глобальной тёмной темы нет и
`prefers-color-scheme` намеренно не слушается — витрина выглядит одинаково у
всех.

## Данные о товарах

Фотографии настоящие — это съёмка дома. **Всё остальное в карточках
демонстрационное**: названия это номера образов («Образ 01»), цены, сроки и
наличие вымышлены и так помечены.

Определять характеристики изделия по фотографии запрещено: нельзя записать в
карточку, что на кадре чакан, атлас или адрас, указать регион, технику или
состав. Поэтому `attributes` пустые, а цвет как поле не заведён. Настоящие
подписи и цены вносятся через админку — код при этом не меняется.

## Ждём от клиента

- Названия, состав и цены изделий.
- Второй проход отбора съёмки для каталога и карточек.
- Домен (`src/lib/config/site.ts`) и условия доставки — сейчас «согласовывается
  отдельно».
- Вычитку таджикских строк носителем языка.
- Решение, нужны ли языковые адреса (`/tg/…`) для поиска — сейчас язык в куке.

## Границы

Без отдельной постановки не добавляются: онлайн-оплата и интеграция Alif,
личные кабинеты, уведомления через WhatsApp Business API (сейчас — ссылка
`wa.me` с готовым текстом). Услуги, адреса, часы работы, история бренда и
характеристики вещей не придумываются — только то, что подтвердил клиент.
