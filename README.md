# ARUS DOMOD

Витрина таджикского свадебного костюма: **продажа и прокат** платьев, украшений
и аксессуаров. Фронтенд-MVP — задача проекта показать клиенту визуальный
уровень будущего продукта, а не запустить магазин.

Дом моды из Душанбе. Интерфейс на русском, названия разделов дублируются на
таджикском.

```bash
npm install
npm run dev        # http://localhost:3000
```

---

## Что это

Сайт устроен как разворот модного журнала, а не как витрина товаров. Секции не
ставятся друг на друга шаблоном «баннер → четыре карточки → текст», а
подшиваются друг к другу **ҳошия** — тканой каймой по краю. Светлые и чёрные
секции чередуются, повторяя ритм полос атласа.

Национальное здесь работает внутри luxury fashion, а не вместо него: палитра
выведена из таджикского текстиля (небелёный хлопок чакана, чёрный грунт атласа,
марена, латунь сюзане, индиго ковровой каймы), орнаменты — четыре реальных
мотива, отрисованные CSS-масками.

| Раздел                | Что там                                                       |
| --------------------- | ------------------------------------------------------------- |
| `/`                   | Главная: семь редакционных секций со сменой поверхности       |
| `/catalog`            | Каталог с фасетными фильтрами, сортировкой и поиском          |
| `/catalog/[category]` | Тот же каталог с предвыбранным разделом                       |
| `/product/[slug]`     | Страница образа: галерея, полноэкранный просмотр, предложения |
| `/cart`, `/favorites` | Корзина и избранное, живут в `localStorage`                   |
| `/checkout`           | Прототип оформления — **без реальной оплаты**                 |

## Стек

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS v4.

Зависимости ровно те, что создаёт `create-next-app`. Ни одной библиотеки сверх
этого: анимации, иконки, склейка классов, орнаменты и логотип сделаны своими
средствами. Библиотека анимаций не подключена намеренно — reveal, наезд и
кроссфейд это transform и opacity, ставить ради них 50 КБ рантайма нельзя.

Бэкенда, базы, авторизации, оплаты и админки в проекте нет.

### Два решения, которые стоит знать до первой правки

**Шов данных.** Страницы и компоненты никогда не импортируют товары напрямую —
единственная дверь это `catalog()` из `src/lib/catalog`. Переход на настоящий
API это замена одного импорта в `src/lib/catalog/index.ts`; ни одна страница и
ни один компонент при этом не меняются. Деньги везде хранятся целыми минорными
единицами (дирамами) с кодом валюты, цена живёт в `offers[]` — потому что один
и тот же образ может одновременно продаваться и сдаваться в прокат.

**Поверхности.** Тон задаётся атрибутом `data-surface` на секции, а не классами
на каждом элементе. Внутри переключаются все семантические токены сразу,
поэтому один и тот же компонент верно выглядит и на светлой, и на чёрной секции
без `dark:`-вариантов. Глобальной тёмной темы у сайта нет и
`prefers-color-scheme` намеренно не слушается: витрина обязана выглядеть
одинаково у всех.

## Данные о товарах

Фотографии в проекте настоящие — это съёмка ателье. **Всё остальное в карточках
синтетическое** и помечено как демонстрационное: названия это номера образов
(«Образ 01»), цены, сроки проката, залоги и наличие вымышлены.

Определять характеристики изделия по фотографии в этом проекте запрещено.
Нельзя записать в карточку, что на кадре чакан, атлас или адрас, указать
регион, технику вышивки или состав ткани: это чужие вещи, и догадка,
попавшая в карточку, становится ложным утверждением о них. Поэтому
`attributes` не заполняется вовсе, а цвет не заведён как поле — иначе он
выводился бы с фотографии, — и фильтра по цвету в каталоге нет.

Когда ателье передаст настоящие подписи и цены, меняется один файл:
`src/lib/catalog/mock-data.ts`.
