# ARUS DOMOD — frontend

Интернет-магазин таджикского свадебного костюма: продажа и **прокат** нарядов,
украшений и аксессуаров. Работающий магазин: база, заказы, WhatsApp, админка,
три языка. Витрина — цифровой флагман дома, а не шаблонный e-commerce.

Тексты интерфейса и комментарии в коде — на русском; интерфейс переведён
на таджикский и английский через словари.

## Команды

```bash
npm run dev        # http://localhost:3000
npm run build      # продакшн-сборка (она же гоняет TypeScript)
npm run typecheck  # tsc --noEmit
npm run lint       # eslint
```

`npm run typecheck` на свежем клоне падает на типах маршрутов, пока не выполнен
`next build` или `npx next typegen`.

## Стек

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS v4 ·
`node:sqlite` (Node 24). Ни одной библиотеки сверх `create-next-app`:
анимации, иконки, орнаменты, база, сессии — своими средствами.

# Визуальное направление — система «САҲН»

Саҳн — двор. Сайт устроен как белый двор, на котором стоят **айвоны**: глубокие
зелёные объёмы с настоящей тенью, а в их нишах — фотографии. Золото — нить в
облицовке: линия, цифра, угол, шов. Никогда не заливка и не кнопка.

Формула: **белый холст × зелёные объёмные секции × золотые детали × таджикское
наследие × luxury fashion × редакционная композиция × движение.**

## Чего не делаем

- Одинаковых секций. У каждого блока своя идея: кадр выходит из объёма, объём
  сдвинут под кадр, рейка предметов уходит за край, карточка лежит на углу.
  «Зелёный прямоугольник → зелёный прямоугольник» — запрещённый ритм.
- Шаблонной раскладки «текст слева, фото справа, кнопка под текстом».
- Дешёвого объёма: одного размытого пятна вместо тени, чёрных теней,
  glassmorphism, свечений, пластика.
- Капсул везде. Капсула — только чипы, счётчики и навигация в шапке.
- Золотого текста на белом (3.3:1): золото там — линия, рамка, крупная цифра.
- Выдуманных цифр. Анимируются только настоящие числа из данных.

# Design system

Единственный источник правды — `src/styles/tokens.css`. Компоненты используют
**только** семантические токены и утилиты из `@theme` (`bg-page`,
`text-ink-accent`, `shadow-card`, `rounded-card`). Сырые ступени
(`--firuza-*`, `--zar-*`, `--shir-*`) вне `tokens.css` не используются;
исключения задокументированы в `Tag.tsx` и `FabricPlate.tsx`.

## Поверхности

Три поверхности, у каждой полный набор семантики. Задаются `data-surface`:

| Поверхность          | Что это                                         | Где                           |
| -------------------- | ----------------------------------------------- | ----------------------------- |
| `day` (по умолчанию) | белый двор, тёмно-зелёный текст, зелёная кнопка | холст страницы, карточки      |
| `green`              | айвон #054745, кремовый текст, кремовая кнопка  | секции-объёмы                 |
| `night`              | глубокая ниша #03211F                           | подвал, меню, просмотр кадров |

Внутри поверхности переключаются **все** токены сразу, поэтому один компонент
верно выглядит на белом и в айвоне без `dark:`-вариантов. Глобальной тёмной
темы нет и `prefers-color-scheme` не слушается.

## Объёмы

- `<Aivan>` (`src/components/layout/Aivan.tsx`) — зелёный блок: радиус
  `--radius-block` (20–32px), тень `--shadow-block` (три слоя: кромка, ближняя,
  дальний ореол) плюс внутренняя кромка `--shadow-inset`. `arch` — арочный
  верх; `clip={false}` — когда кадр намеренно выходит за границу; `ornament`
  — дамаск в углу, растворяющийся к центру.
- `.card` / `.card--float` — белый предмет на поверхности, радиус
  `--radius-card` (16–24px). `.lift` — подъём на 4px с ответом тени.
- `<Section>` — только ритм полосы (`py`), поверхность по умолчанию `day`.
- Кнопки: радиус 14px (`rounded-md`), подъём при наведении; чипы — капсулы.
- **Тоқча — главный ход системы.** `<Media radius="arch">` (или `.arch`)
  делает купол ниши силуэтом самой фотографии: горизонтальный радиус 50%,
  поэтому верхние углы смыкаются в настоящую дугу. Подъём `--arch-rise`
  ограничен через `min()`, и широкий кадр сам получает пологий свод.
  **Под кадром в арке не бывает карточки.** Белая подложка вокруг
  скруглённого кадра — это две поверхности подряд; вложенные поверхности
  читаются как интерфейс, собранный из готовых блоков. `.arch-hoshiya`
  добавляет золотую нить по дуге.
- Кадры через `<Media>`: `radius="arch" | "arch-low" | "card" | "block" |
"sm" | "none"`, `sizes` обязателен, наезд `scale(1.04)` внутри `group`.

## Цвет

Палитра выведена из логотипа: зелень — медиана знака, золото — латунь 37°.

- Белый двор `#FFFFFF`, тёплые подложки `--shir-100/200`.
- Айвон `--firuza-800`, ниша `--firuza-950`; текст на них — крем `#F2EADB`.
- Золото: на белом `--zar-700` (линии, крупные цифры), на зелёном `--zar-300`
  (подписи, 7:1). `--gold-bright` — счётчики в шапке.
- Акцент кнопок: на белом зелёный, на зелёном кремовый. Золото — никогда.

## Типографика

Cormorant (витринный крой) + Golos Text — единственная пара с полным
таджикским набором **ӯ ҳ ҷ қ ғ ӣ** (`cyrillic-ext` обязателен, покрытие
проверяется замером глифа, а не списком subsets; подробности в `layout.tsx`).

Роли из `src/styles/base.css`: `t-giant` (имя дома больше страницы),
`t-display-1/2`, `t-h1/h2/h3`, `t-num` (крупная цифра антиквой), `t-lead`,
`t-body`, `t-body-sm`, `t-caption`, `t-label`, `t-label-wide`, `t-vertical`
(подпись на рейке), `t-price`. Произвольные размеры в разметке запрещены.
Заголовки — антиквой, вес 400. CAPS — только `t-label`.

**Кикеров над заголовками нет.** Подпись caps над h1/h2 («КОЛЛЕКЦИЯ 01»,
«О БРЕНДЕ») — самый частый признак шаблона: заголовок держит вес сам.
Номер секции ставится только там, где последовательность и есть содержание
(шаги заказа, кадры галереи, шаги оплаты), а не для украшения.

## Орнамент

`src/styles/ornament.css`, компоненты в `src/components/ornament/`. Пять ролей:
ҳошия (золотая линия, `.hoshiya-line`, `.hoshiya-seam` с точкой), тоқча
(`.toqcha[data-open]` — разомкнутая ниша), угол (`.gold-corners`), рамка
(`.gold-frame`), дамаск (`.ornament--damask`, `.ornament--fade` — поле в углу).
Мотивы через CSS `mask`, красятся `currentColor`. Не больше одного орнамента
на смысловую зону; всегда `aria-hidden`; под текстом орнамента не бывает.

## Движение

Медленно, тихо, без пружин. Токены `--dur-*`, `--ease-quiet|silk`.
Примитивы в `base.css`: `<Reveal>` (`.motion-reveal`), `.motion-line`
(линия прорастает при появлении родителя), `.motion-drift` (параллакс на
scroll-driven animations, прогрессивное улучшение), `.motion-zoom`,
`.motion-arrow`, `.motion-underline`, `.motion-enter|veil` (первый экран),
`.motion-drawer|fade` (панели), `.lift`, `.rail` (горизонтальная лента со
snap), `.rail-edge` (кромка ленты показывает, что она продолжается).
`<CountUp>` — только для настоящих чисел. `prefers-reduced-motion` глушит
всё в `base.css`.

**Авторский момент один: `.motion-unveil`** — купол раскрывается маской от
основания к замку свода, и только на первом экране. Одинаковое появление
снизу вверх на каждой секции — это не движение, а тик.

**Поверхности браузера оформлены в `base.css`:** каретка, `::placeholder`,
`::marker`, `accent-color` (галочки и радио были системными синими),
полоса прокрутки, подсветка касания, отступ подчёркивания. Их пропуск —
самый заметный признак, что страницу собрали, а не сделали.

## Раскладка

Поля даёт `<Container>` через `--gutter`; внутренние поля объёма —
`--block-pad`. Брейкпоинты Tailwind плюс `xs` 480px и `2xl` 1600px.
Мобильная композиция — своя, а не сжатый десктоп: hero становится
вертикальной сценой, подборка — рейкой, меню — оглавлением антиквой.
Проверяется на 320 · 375 · 390 · 430 · 1440.

## Фотографии

Съёмка дома лежит в `фото товаров/` (исходники), отобранное — в
`public/photo/`, манифест — `src/lib/photos.ts` (`photo(slug, alt)`,
`hasPhoto(slug)`). Alt переводится через `t.alts.*`. У образа до двух кадров.
Пока кадра нет, `<Media>` рисует тканую плиту (`FabricPlate`).
Новых изображений, генерации и поиска картинок в проекте нет.

## Страница образа

`/product/[slug]`. Композиция редакционная: кадры занимают семь колонок из
двенадцати и прокручиваются, колонка с ценой прилипает рядом — подпись к
развороту, а не товарный блок сбоку.

- **Кадры лежат стопкой, а не в карусели.** Второй уходит вправо более узкой
  колонкой, как врезка на развороте. Раскладка одна на все экраны, меняется
  направление: на телефоне это лента со snap-прокруткой. Двух наборов разметки
  быть не должно — браузер декодировал бы скрытые кадры заодно с видимыми.
- **Полноэкранный просмотр** — та же лента на scroll-snap. Активный кадр
  выводится **из позиции прокрутки**, а не наблюдателем пересечений: у
  прокрутки один источник правды, и она не зависит от видимости вкладки.
- Плавная прокрутка галереи глушится при `prefers-reduced-motion`.
- **Ничего пустого не рисуется.** Одно предложение — переключателя нет;
  размеров у изделия не бывает — нет и ряда размеров; один кадр — нет ни
  счётчика, ни миниатюр, ни стрелок. Пустой селектор врёт о товаре не меньше,
  чем выдуманная характеристика.
- Липкая панель телефона появляется, когда основной CTA уехал, и прячется на
  секции `PRODUCT_STORY_ID` — иначе она навсегда закрыла бы низ подвала.
- Раздел после hero говорит о подходе дома, а не о конкретном изделии.

## Корзина, избранное, оформление

`src/lib/cart.ts` и `src/lib/favorites.ts` устроены одинаково: хранилище вне
React, подписка через `useSyncExternalStore`, снимок пересобирается только при
изменении (новый массив на каждый вызов увёл бы React в бесконечный рендер).

Оба переживают перезагрузку через localStorage. **Восстановление идёт при
первой подписке, а не во время рендера** — то есть уже после гидратации: иначе
сервер отдал бы пустое состояние, клиент при первом рендере восстановленное, и
React сообщил бы о расхождении разметки. Данные из хранилища проверяются по
форме (`src/lib/storage.ts`): непрошедшее молча отбрасывается.

**Строки корзины хранят только идентификаторы.** Названия, кадры и цены
страница берёт из репозитория по slug (`useCartProducts`), поэтому второй
копии данных о товаре нет. Покупка и прокат разведены в отдельные группы;
залог показан отдельной строкой и **не входит в итог** — он возвратный.

`/checkout` — прототип: нативная форма, проверка браузером, состояние
«принято» без номера заказа. Оплата — `PaymentPlaceholder`: ни ключей, ни
запросов, ни имитации ответа. Подключение Alif сведётся к замене компонента.

Cart, Favorites и Checkout спокойнее витрины: человек пришёл совершить
действие, а не рассматривать кампанию.

## Каталог

Состояние живёт в одном месте — `CatalogView`. Он собирает `CatalogFilters`,
превращает их в `CatalogQuery` и спрашивает репозиторий; остальные компоненты
каталога презентационные.

- **Флага «идёт загрузка» нет.** Выдача хранится вместе с ключом запроса,
  который её породил (`queryKey`), и устаревание выводится сравнением ключей.
  Флаг, который надо не забыть сбросить, — источник вечных багов.
- **Фасеты решают, что показывать.** `listFacets()` считает каждую грань по
  товарам, прошедшим все прочие фильтры, кроме неё самой: счётчики не
  обнуляются, а грань без значений не рисуется вовсе.
- Категория управляется рядом разделов, а не панелью фильтров: два элемента
  управления одним полем сбивают с толку.
- Раппорт сетки — семь карточек: ряд из четырёх компактных, затем ряд из трёх
  покрупнее. Ряды всегда складываются ровно в 12 колонок, поэтому дырок не
  бывает и `grid-auto-flow: dense` (который ломает порядок сортировки) не
  нужен. **Внутри ряда пропорция кадра одна на всех** — иначе рядом с высокой
  карточкой зияет пустота. Ритм задаётся сменой калибра, а не карточками во
  весь экран: такие приходится листать вслепую.
- На телефоне ритма нет намеренно: две ровные колонки.
- Поиск ищет по названию, имени категории и артикулу. Отдельной страницы
  поиска нет: оверлей открывается поверх текущего экрана.

## Данные о товарах: чего писать нельзя

Фотографии в проекте настоящие — это съёмка ателье. Всё остальное в карточках
синтетическое, и так помечено в `mock-data.ts`.

**Определять характеристики товара по фотографии запрещено.** Нельзя написать,
что на кадре чакан, атлас или адрас; нельзя указать регион, технику вышивки,
состав ткани или срок работы мастера. Это чужое изделие: догадка, записанная
в карточку, становится ложным утверждением о нём — и клиент увидит на своём
сайте неверные сведения о собственных вещах.

Так уже было: карточки получили названия вроде «Чакан «Сурхи Кӯлоб»» и
характеристики «шёлк, золотая нить, Кӯлоб» — всё выведено из снимка и всё
пришлось убрать. Пока данных нет:

- название — номер образа: «Образ 01», `slug: look-01`;
- цены, сроки проката, залоги, размеры и наличие — вымышленные и помечены
  как демонстрационные;
- `attributes` не заполняется вовсе;
- цвет как поле данных не заводится (иначе он выводился бы с фотографии),
  поэтому и фильтра по цвету в каталоге нет.

Нумерация образов — витринная конвенция, а не заглушка: дома моды нумеруют
выходы коллекции. Придут подписи — меняется один файл.

## Шов данных — главное архитектурное решение

Страницы и компоненты **никогда** не читают товары напрямую. Двери две, обе
отдают один контракт `CatalogRepository`:

```
src/lib/catalog/
  repository.ts         контракт CatalogRepository
  engine.ts             чистый движок запросов над снимком CatalogData:
                        фильтры, фасеты, сортировка, поиск, пагинация
  sqlite-repository.ts  движок над базой (сервер)
  index.ts              серверная дверь: catalog()
  client.ts             клиентская дверь: тот же контракт поверх /api/catalog
  mock-data.ts          демо-каталог — им засевается пустая база
```

Серверный код (страницы, `generateMetadata`, sitemap, заказы) импортирует
`@/lib/catalog`; клиентские компоненты (`CatalogView`, поиск, корзина) —
`@/lib/catalog/client`. Серверная дверь тянет `node:sqlite`, поэтому её импорт
в клиентский компонент ломает сборку — это и есть проверка границы.

Контракты в `src/types/catalog.ts` учитывают то, что дороже всего чинить
задним числом: деньги — целые **минорные единицы** плюс код валюты (форматирует
`formatMoney()`, float-цен в компонентах нет); цена живёт в `offers[]`, потому
что вещь может и продаваться, и сдаваться; списки всегда `Paginated<T>`;
в маршрутах `slug`, `id` внутренний, а имя категории карточка получает
отдельным пропом — `categorySlug` она не показывает.

## Конвенции компонентов

- Клиентские компоненты — только там, где есть состояние или DOM API.
- `cn()` не разрешает конфликты Tailwind-классов (tailwind-merge не подключён):
  компонент отдаёт базовые классы, вызывающий — только непересекающиеся.
- Интерактив карточка принимает **слотом** (`action` в `ProductCard`).
- У шапки есть `backdrop-filter`, а он создаёт containing block для
  `position: fixed`. Любой полноэкранный оверлей внутри шапки обязан рендериться
  порталом в `document.body` — иначе `inset-0` схлопывается до высоты шапки.

### Зависимости эффектов — по значениям, а не по ссылкам

`listFacets()` возвращает новый объект `{min, max}` при каждом вызове. Мемо по
его идентичности пересчитывался всегда, дальше пересобирался запрос, менялись
зависимости эффекта, эффект снова шёл за данными — и так без конца. Страница
простаивала, а главный поток был занят: **именно отсюда брались «залипающие»
клики**, а не из оверлеев и не из анимаций.

Правила, которые из этого следуют:

- зависимостями эффектов и `useMemo` служат **примитивы** (числа, строки), а не
  объекты и массивы, пришедшие из данных;
- обновление состояния, полученного асинхронно, сверяется с ключом запроса:
  `setData(prev => prev.key === nextKey ? prev : next)` делает цикл
  невозможным структурно, а не по договорённости;
- обработчики, которые уходят в зависимости эффектов (`onClose` и подобные),
  оборачиваются в `useCallback` на месте вызова.

Проверка: временно нарастить счётчик в теле эффекта и открыть страницу. Если
число растёт при бездействии — цикл есть.

### Конфликт утилит одного уровня — самая частая ловушка проекта

Две Tailwind-утилиты одного свойства и одного уровня (`inline-flex` и `hidden`,
`px-7` и `px-0`, `relative` и `absolute`) разрешаются **порядком в
сгенерированном CSS, а не порядком в атрибуте `class`**. `cn(base, "hidden")`
не гарантирует, что победит `hidden`.

Ловушка срабатывала пять раз (display у иконок, поля ghost-кнопки, фон шапки,
подложки в двух секциях). Правило: если у варианта компонента своё значение
свойства, базовая строка это свойство **не задаёт** вообще (см. `iconBox` в
`SiteHeader`, `paddingClass` в `Button`). Нужна другая позиция — заворачивайте
в обёртку. Варианты с разным брейкпоинтом (`hidden sm:inline-flex`) безопасны.

### Шапка

`SiteHeader` — клиентский компонент с двумя состояниями. Список маршрутов с
тёмным первым экраном — `OVERLAY_ROUTES`; на них шапка прозрачная и лежит
внутри кадра, после прокрутки уезжает на высоту бегущей строки, садится на
глубокую бирюзу и проявляет золотую ҳошия вместо тени; светлой не становится
никогда. Состояние держится в React: вместе с фоном переключается поверхность.

# Бэкенд, заказы, админка, языки

База — `node:sqlite` (Node 24, без зависимостей), файл `data/arus.sqlite`
(`ARUS_DATA_DIR`). `src/lib/db/sqlite.ts` держит одно соединение на процесс и
при пустой базе засевает её из `mock-data.ts`; `catalog-store.ts` кэширует
снимок каталога и сбрасывает его при записи. Товары и категории лежат
JSON-документами: схема каталога меняется в `src/types/catalog.ts`, а не в SQL.

**Заказы** (`src/lib/orders/`): `createOrder` проверяет строки по каталогу и
снимает цены на момент заказа в сам заказ — каталог потом может измениться.
Прокат в заказ не принимается (400): он оформляется только в магазине. Номер
`AD-0001`, статусы — `ORDER_STATUSES`, подписи — `labels.ts`. Уведомление —
ссылка `wa.me` с текстом из `whatsapp.ts` (основной номер Азиза, второй
Рустам), Business API нет. Оплаты нет по решению клиента: `PaymentPlaceholder`
— шов для Alif, ни ключей, ни запросов, ни имитации ответа.

**Админка** `/admin`: пароль `ADMIN_PASSWORD`, кука подписана HMAC
(`src/lib/admin/session.ts`, Web Crypto — работает в proxy). `src/proxy.ts`
закрывает `/admin/*` и `/api/admin/*`. Формы — серверные действия; после записи
`revalidatePath("/", "layout")`, поэтому правка видна на витрине сразу. Кадры
загружаются в `data/uploads/` и отдаются маршрутом `/uploads/[...path]`:
`public/` в сборке заморожен. Оболочка панели — `data-surface="day"`, без
редакционной подачи: это рабочий инструмент.

**Языки** (`src/lib/i18n/`): кука `arus_locale`, ru · tg · en, адреса общие.
`Dictionary` выводится из русского словаря типом `Shape<T>`, поэтому
пропущенный ключ в переводе — ошибка компиляции. Сервер — `getDictionary()`
(`server.ts`, тянет `next/headers`), клиент — `useDictionary()` из
`LocaleProvider`. Импорт `server.ts` в клиентский компонент роняет весь сайт —
так уже было с `PaymentPlaceholder`. Подписи навигации — `navLabel`,
категорий — `categoryTitle`; названия образов не переводятся, это данные.

Витрина лежит в группе `(site)` со своей шапкой и подвалом; `admin/` — вне её.

## Состояние

Готов полный путь: главная → каталог → образ → корзина → оформление → заказ
в базе → WhatsApp → админка. Плюс прокат, «О нас», «Доставка», «Контакты»,
избранное, sitemap/robots, Product JSON-LD. Деплой — долгоживущий Node с
диском; serverless без замены хранилища не подходит.

## Границы, которые нельзя переходить

Без отдельной постановки не добавляются: онлайн-оплата и Alif, личные
кабинеты, WhatsApp Business API, i18n-роутинг по адресам. Услуги, адреса,
часы работы, история бренда, характеристики вещей — только подтверждённые.

## Бренд: только подтверждённые данные

`src/lib/config/site.ts` — единственный источник: имя, профиль
`arus.domod.tj`, «Королевские наряды для невест и женихов», «Продажа и прокат
в национальном стиле», телефоны Азизы и Рустама, Душанбе, Instagram и YouTube,
условия проката. Числовое утверждение о количестве пар из профиля не
используется: в оригинале оно выглядит опечаткой.

Логотип — `/logo.png`; производные в `public/brand/` получены **только
кадрированием и сжатием**: `-logo.jpg` подвал, `-mark.jpg` шапка, `-og.jpg`
Open Graph, `src/app/icon.png` вкладка. Полный лок-ап в шапку не ставится:
при 68px надпись была бы в три пикселя. Цвета логотипа — источник «Фирӯзы».
